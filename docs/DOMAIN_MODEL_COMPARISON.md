# Domain Model Comparison

NetCyberAI's actual live schema (44 tables, `mcp__Supabase__list_tables`
against `netcyberai-dev`, re-confirmed 2026-09-24) versus the data models of
the four directly-mined reference repos (`GITHUB_REFERENCE_MINING.md`) and the
five previously-mined open-source ERPs (`12_RECONSTRUCTION_INVESTIGATION.md`
§6). Only real, concrete deltas are listed — not a restatement of every table.

| Domain | NetCyberAI (live schema) | Reference repos | Gap? |
|---|---|---|---|
| Academic session/term | **No first-class table.** `academic_year` exists only as a text column on `fee_structures` (`supabase/migrations/20260917072616_fee_engine.sql:33`) — nowhere on `classes`, `students`, `exams`, or `attendance`. | Nahyomee's schema has a dedicated `Sessions`/`terms` concept referenced across the board; every ERP studied (Frappe Education, Gibbon, etc.) has one. | **Yes — real gap.** Every record that should be scoped to a school year (promotion, report cards, timetable, admissions cohort) currently has no year/term to scope against except fees. Needs its own migration before Prompt J (academics) or exams/report cards ship. |
| Class/section | `classes.name` is free text (`'8-A'`) — class and section are not separate columns (`db/schema.sql`). | Nahyomee/most ERPs model `Classroom`/section as distinct fields or a separate table. | **Minor gap.** Fine for display today; becomes a real problem once timetable, cross-section reporting, or "all sections of Class 8" queries are needed. Not urgent — flag for the U9 (Academics/timetable) prompt, don't fix speculatively now. |
| Homework | **No table exists.** Confirmed: no `homework` table in `db/schema.sql` or any migration; `/app/class-notices` and academics pages are stub. | WangilaWakhongola, Alisha1402, TemiKayode, and every ERP in the prior study all have homework/assignment modules. | **Yes — real gap**, already known and already scoped as Tier B in `11_MASTER_REBUILD_PLAN.md` (U9). Not new information, just confirmed still true. |
| Timetable | **No table exists.** | All four newly-mined repos plus the five ERPs have one. | Already scoped Tier B / U9 in the master plan — confirmed still accurate, not new. |
| Notices/circulars | **No table exists** (the `/app/class-notices` stub page has nothing behind it). | Alisha1402 has a categorized notice board; WangilaWakhongola doesn't list one explicitly. | New, small gap not previously itemized by name in the Gap Register — worth adding as a line item under U9/U10 (it's a simple table + list UI, low effort, real day-to-day value). |
| Parent/guardian model | `parents` + `parent_student_map` (many-to-many, supports siblings) — already more explicit than most references. | WangilaWakhongola's README doesn't mention a distinct parent table at all (implies parent = a `Student.guardian` field); Nahyomee's schema doesn't list a separate parent table either. | **NetCyberAI is ahead here**, not behind — no action needed, cited for balance since this document isn't only meant to surface gaps. |
| Fee model currency handling | `fee_heads`/`fee_structures`/`payments` use `amount_minor` + `currency` (jurisdiction-neutral, hardened this session per PR #10). | Alisha1402 hardcodes ₹ throughout ("Tuition, Admission, Examination... Fee in ₹"); WangilaWakhongola supports M-Pesa (Kenyan) natively but doesn't appear currency-neutral either. | **NetCyberAI is ahead here too** — the currency-neutral design already avoided a mistake most of the small reference repos made. No action needed. |
| Append-only financial/audit tables | `payments`, `consent_ledger`, `audit_log`, `webhook_events` have UPDATE/DELETE revoked from app roles (hardened PR #10, enforced by `check_append_only_grants.py`). | None of the four newly-mined repos show any equivalent append-only discipline in their schemas — payments/attendance tables appear to be ordinary mutable tables in all of them. | **NetCyberAI is ahead here** — a genuine differentiator at the data-integrity level, not just product-feature level. Worth remembering when the founder asks "why does this look incomplete" — some of what looks like "less feature" is actually "more correct." |
| Aadhaar/sensitive-ID storage | Explicitly **not stored** (Constitution/Prompt F rule; OCR captures documents without persisting the raw Aadhaar image). | Alisha1402 explicitly stores "Aadhaar records" as a plain student field. | NetCyberAI's existing restraint here is correct and should stay locked — cited as a REJECT-pattern confirmation, not a gap. |
